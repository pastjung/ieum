# 이슈 초안 작성 절차

1. 유형을 판단한다: 기능 제안 → Feature, 버그 → Bug, 설정·문서·리팩터링 등 → Chore.
2. `.gitlab/issue_templates/`의 해당 템플릿 구조대로 본문을 채운다. Bug는 재현 절차를 재현 가능한 수준으로 구체적으로.
3. 제목은 한 줄 요약, 라벨 제안을 덧붙인다.
4. 착수할 때 쓸 브랜치 이름도 함께 제안한다 (`<type>/<이슈번호>-<도메인>-<기능>` — 번호는 등록 후 확정).
5. 제목·본문을 코드블록으로 출력한다. **이슈를 임의로 등록하지 않는다.**
