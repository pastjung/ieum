# 린트 지적 해결 절차

1. 해당 앱의 검사를 실행해 지적 전체를 수집한다 (명령은 AGENTS.md 검증 명령).
2. 지적을 세 갈래로 분류한다:
   - **자동 수정 가능** → 도구에 맡긴다: `ruff check --fix` / `eslint --fix` / `./gradlew spotlessApply`. 손으로 고치지 않는다.
   - **판단이 필요한 코드 문제** (네이밍, 구조, 타입 오류) → 해당 앱의 docs/conventions/code/<앱>.md 규칙에 맞게 코드를 고친다. 동작이 바뀔 수 있는 수정은 사용자에게 먼저 확인한다.
   - **오탐 (프레임워크 관용구를 도구가 모르는 경우)** → 코드를 비틀지 말고 설정에 예외를 명시한다 (예: FastAPI Depends의 B008 → pyproject의 extend-immutable-calls). 예외에는 이유 주석을 남긴다.
3. 검사를 재실행해 0 오류를 확인한다.
4. 오탐 예외를 추가했으면 그 판단 근거를 커밋 메시지에 남긴다 — 다음 사람이 같은 고민을 반복하지 않도록.
