## 1. 사용자와 공통 화면 원칙

LEARNER는 Android 모바일에서 학습하고 INSTRUCTOR는 웹에서 문제·수업을 운영한다. ADMIN의 공개 화면은 제공하지 않는다. 한 계정은 한 역할만 갖는다. 화면 상태·오류는 색상 외 표현과 음성·햅틱·시각 정보로 전달한다. 접근성 설정은 계정별 프론트 로컬에 유지한다.

<a id="journey-onboarding"></a>
## 2. J-01 가입·최초 학습 진입

| 순서 | 사용자 행동 | 화면과 처리 |
| --- | --- | --- |
| 1 | username·이메일·비밀번호로 가입 | 학습자 계정 생성 후 이메일 인증 안내 |
| 2 | 이메일 인증 완료 후 로그인 | 인증되지 않은 계정은 학습을 시작할 수 없음 |
| 3 | 자가 진단에서 안다·모른다 선택 | 첫 모르는 단계로 이동. 모두 안다면 L6까지 열고 복습 단계 선택 |
| 4 | L0 사용 안내 확인 또는 건너뛰기 | 설정·도움말에서 다시 열 수 있음. 장치 연결 필수 아님 |
| 5 | 선택 단계 학습 시작 | 최고 해금 단계와 이번 단계에 맞는 완성된 세션 준비 |
| 6 | 첫 문제 진입 | 준비 실패 시 재시도 안내. 수준 설정만 따로 완료하지 않음 |

정확한 여섯 질문은 [커리큘럼의 자가 진단](./curriculum.md#self-assessment)을 따른다. 개별 응답은 시험 점수·숙련도로 처리하지 않는다. 재로그인 후 사용자 요약의 level을 확인한다. 학습자의 level이 null이면 자가 진단으로, L1~L6이면 열린 단계 선택과 현재 세션 확인으로 연결한다.

이메일 인증·비밀번호 복구 요청은 계정 존재나 실제 발송 여부를 구분하지 않는 안내를 표시한다. 비밀번호 재설정 후에는 다시 로그인한다. 로그아웃은 현재 기기의 인증을 종료한다. 탈퇴는 현재 비밀번호를 확인한 뒤 접근을 종료하며 취소·복구는 제공하지 않는다. 재가입하면 새 사용자로 시작한다.

## 3. J-02 개인 학습·맞춤 복습

| 순서 | 사용자 행동 | 화면과 처리 |
| --- | --- | --- |
| 1 | 열린 단계에서 학습·복습 선택 | 같은 단계의 중단 세션이 있으면 이어하기. 다른 단계로 바꾸려면 현재 세션 완료 필요 |
| 2 | 문제 목표·조작 방법 확인 | 미제출 문항의 정답 점형은 숨김 |
| 3 | Cell을 입력하고 제출 | 서버에 저장된 최종 채점 결과를 표시. 저장 실패는 성공으로 표시하지 않음 |
| 4 | 정오답·차이·정답 확인 | 필요하면 음성·햅틱·아두이노로 확인하고 따라 하기. 최초 결과 유지 |
| 5 | 다음 문항 진행 | 서로 다른 5문제를 두 번씩, 총 10문항. 같은 문제 연속 배정 없음 |
| 6 | 마지막 문항 제출 | 학습 완료·분석 대기 표시 후 분석 요청 |
| 7 | 분석 결과 확인 | 이번 세션 요약과 현재 숙련 상태 표시 |
| 8 | 다음 학습 시작 | 갱신된 취약점·열린 단계에 맞춰 새 문제 구성 |

### 중단·재접속

앱을 닫았다가 돌아오면 저장된 세션과 제출 결과를 복구하고 아직 제출하지 않은 가장 앞 문항을 보여 준다. 제출 전 입력은 서버 복원 대상이 아니다. 이미 제출한 문항은 기존 결과를 보여 주며 따라 하기로 덮어쓰지 않는다. 세션 포기·초기화·자동 만료는 제공하지 않는다.

응답을 받지 못한 제출은 같은 제출로 재시도한다. 저장된 결과가 있으면 그 결과를 돌려주고 중복 풀이로 세지 않는다. 여러 기기에서 같은 문항을 제출하면 서버에 확정된 한 결과를 기준으로 화면을 맞춘다.

### 분석 대기·완료

완료 후 분석 중 앱이 닫혀도 분석 대기 상태를 복원한다. 분석이 실패하면 완료한 답안을 유지하고 분석만 재시도하며 성공 전에 다음 개인 세션을 만들지 않는다. 완료 세션의 문항별 결과는 상세 조회에서 볼 수 있고, 분석 결과 화면은 분석 완료 후 제공한다.

현재 숙련도는 이후 학습으로 달라질 수 있다. 과거 세션 요약과 당시 숙련도 그래프를 같은 것으로 표시하지 않는다. 완료 세션 목록·기간 통계 화면은 MVP에서 제공하지 않는다.

## 4. J-03 학습자의 실시간 수업

| 순서 | 사용자 행동 | 화면과 처리 |
| --- | --- | --- |
| 1 | 숫자 6자리 참여 코드 입력 | 유효한 시작 전·진행 중 수업에 직접 입장 |
| 2 | 시작 전 대기 | 입장만으로 수업을 시작하지 않음 |
| 3 | 강사 음성·현재 문제 확인 | 강사 단방향 음성 수신, 현재 문제 전체 전달 |
| 4 | 직접 답안 제출 | 본인의 결과만 표시. 같은 문제 재전달 시 기존 결과 유지 |
| 5 | 퇴장 또는 연결 복구 | 재입장은 기존 참여 관계 유지. 현재 수업 상태와 본인 결과 복원 |
| 6 | 종료 확인 | 새 답안 제출 차단. 이미 저장된 답안은 유지 |
| 7 | 필요하면 수업 오답 복습 선택 | 열린 단계별 본인 오답을 확인하고 한 단계를 선택 |
| 8 | 개인 복습 시작 | 해당 오답과 일반 추천·기본 문제를 이용한 동일한 10문항 세션 |

LIVE 풀이·수업 종료만으로 숙련도를 갱신하지 않는다. 이후 개인 복습 세션을 완료·분석할 때 반영한다. 복습 가능한 단계가 하나면 기본 선택할 수 있고 여러 개면 사용자가 고른다. 없으면 일반 개인 학습으로 이동한다. 수업을 종료한 뒤에는 재입장할 수 없지만 기존 참여자는 수업 상세의 본인 정보를 조회할 수 있다.

OpenVidu 음성 연결 실패와 문제·답안 연결 실패를 구분한다. 미디어 접속·복구의 구체 UX는 다음 스프린트 연동 계약에서 확인한다. 학습자 마이크·영상·화면 공유·녹음·다시 듣기는 제공하지 않는다.

## 5. J-04 강사의 문제·수업 운영

1. 문제은행에서 단계·학습 요소·유형·출처 조건으로 문제를 조회하고 상세에서 정답을 검수한다.
2. 새 문제가 필요하면 목표·유형·정답 Cell·학습 요소·단계 연결을 입력한다. 전체 검증에 성공한 문제만 등록한다.
3. 수업을 생성하고 제목·설명·예정 시각과 사용할 문제를 준비한다. 시작 전에는 문제 연결·해제가 가능하다.
4. 참여 코드를 공유하고 수업을 시작한다. 문제 하나를 현재 문제로 지정해 활성 참여자 전체에 전달한다.
5. 진행 중 새 문제 연결·전달은 가능하지만 기존 연결 해제는 제공하지 않는다.
6. 수업을 종료한다. 종료 후에는 신규 제출·문제 변경·재개를 제공하지 않는다.

등록 문제는 수정·삭제하지 않고 변경 내용은 새 문제로 등록한다. 문제는 수업 출제 전에 등록할 수 있다. 개별 대상 출제, 출결 판정, 강사 피드백 저장, 학습자 상세 대시보드·리포트·CSV는 MVP에서 제외한다.

## 6. J-05 촉지·접근성

장치를 검색·연결하고 출력 상태를 확인한다. 정답 확인·따라 하기에서 점형을 출력하고 필요할 때 전체 해제한다. 연결 끊김·출력 실패·시간 초과를 구분해 알리고 모바일 학습을 계속할 수 있게 한다. 장치의 ACK는 출력 명령 처리 정보이며 학습의 정답 판정이 아니다.

TalkBack으로 모든 핵심 화면을 탐색하고 조작할 수 있어야 한다. 입력할 때 탐색 제스처와 6점 입력이 충돌하지 않아야 하며 200% 글자 확대, 색상 외 상태 표현, TTS·햅틱·시각 피드백을 함께 검수한다. 설정은 서버가 아니라 프론트 로컬에 유지되어 초기화 시 다시 설정할 수 있다.

## 7. 공통 예외 흐름

| 상황 | 사용자에게 보이는 처리 |
| --- | --- |
| 세션 콘텐츠 준비 부족 | 학습 준비 불가·재시도 안내. 빈 세션 진입 없음 |
| 추천 실패 | 검증된 기본 문제 학습으로 안내 |
| 답안 검증·저장 실패 | 해당 문항에 머물며 재시도. 성공·완료로 표시하지 않음 |
| 같은 문항의 다른 답안 충돌 | 서버에 저장된 결과 확인, 현재 화면 갱신 |
| 분석 실패 | 완료 답안 유지·분석 재시도 |
| 수업 종료와 제출 경합 | 서버의 확정 결과 또는 종료 안내 표시 |
| 수업 연결 끊김 | 현재 상태 재조회. 종료된 수업은 종료 화면으로 전환 |
| BLE 실패 | 촉지 제한 안내·안전 해제·모바일 학습 지속 |
| 인증 만료·탈퇴 | 재인증 또는 접근 종료. 타인 자료 표시 없음 |

## 8. 여정 검수

자가 진단 모든 분기, 10문항 반복, 정상·오답·재전송·중단·분석 재시도, 실시간 수업 대기·재입장·종료 경쟁, 단계별 수업 복습, 장치 없는 학습을 처음부터 끝까지 검수한다. 한 수업 30명 동시 제출의 데이터 무결성과 상태 복원도 확인한다. 정확한 요청·응답·오류와 저장 제약은 API·ERD 문서에 정의한다.
