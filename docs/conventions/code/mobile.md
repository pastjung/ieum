# 코드 스타일 — mobile (React Native, 학습자 앱)

학습자 앱의 사용자는 시각장애인이다. **접근성은 스타일이 아니라 기능 요구사항**이며, 이 문서에서 가장 중요한 절은 접근성 절이다.

## 자동화 도구

- eslint + prettier (web과 설정 공유, CI 강제 도입 예정), 테스트: jest.

## 접근성 (필수 — 위반은 P1 리뷰 지적)

- 터치 가능한 모든 요소에 `accessibilityLabel`과 `accessibilityRole`을 부여한다. 동작 결과가 자명하지 않으면 `accessibilityHint`를 추가한다.
- 화면 전환·채점 결과 등 중요한 상태 변화는 스크린리더로 전달한다 (`AccessibilityInfo.announceForAccessibility` 또는 TTS 유틸).
- TTS 안내와 햅틱 피드백은 컴포넌트에서 직접 호출하지 않고 공용 유틸(예: `src/a11y/`)을 통해 호출한다 — 정책(속도, 중복 방지)을 한곳에서 제어하기 위함이다.
- 6점 입력 영역은 터치 타깃 크기와 좌표 안정성이 핵심이다. 레이아웃 변경 시 반드시 스크린리더 켠 상태로 직접 조작해 확인한다.
- 색만으로 정보를 전달하지 않는다 (저시력 사용자 대비 명도 대비 확보).
- 새 화면의 완료 조건에 "TalkBack(Android) 시나리오 확인"을 포함한다.

## 네이밍

- web과 동일한 규칙(컴포넌트 PascalCase, 훅 useXxx, 변수 camelCase)을 따른다.
- 점자 도메인 용어: 점자 셀은 `cell`(6비트 정수), 개별 점은 `dot`(1~6). BLE 전송 단위 등 상세는 README의 6비트 표현 절을 따른다.

## 코드 작성

- API 계층 분리, `any` 금지 등 web의 코드 작성 규칙을 공유한다.
- BLE(아두이노 연동) 로직은 화면과 분리된 모듈로 작성한다 — 기기 없이도 화면을 테스트할 수 있어야 한다.
