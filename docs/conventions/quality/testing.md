# 테스트 컨벤션

## 실행 (검증 명령의 원본은 AGENTS.md)

- 로컬: 앱별 명령 (`./gradlew test`, `pytest`, `npm run build`, `npm test`)
- CI 기준: 각 앱 Dockerfile의 test 스테이지 (`docker build --target test`) — MR verify가 실행하는 것과 동일. 로컬과 CI 결과가 다르면 CI가 기준이다.

## 원칙

- 새 기능에는 테스트를 동반한다. 정상 케이스와 실패 케이스를 모두 다룬다.
- 버그를 고치면 같은 버그를 재현하는 테스트를 함께 남긴다 (재발 방지).
- 테스트가 실패하는 상태로 "완료"를 선언하지 않는다.
- 채점·오답 분석처럼 규칙이 명확한 로직(6비트 셀 비교, 누락점/추가점 판정)은 경계값 테스트를 우선한다.

## 네이밍

- backend: 클래스는 `대상클래스명Test`, 메서드는 동작·조건·기대 결과가 드러나게. 한글 메서드명 허용:
  `void 점이_누락되면_오답으로_판정한다()`
- ai: 파일은 `test_*.py`, 함수는 `test_동작_조건_기대결과` (영문 snake_case).
- mobile: jest, `__tests__/` 아래 화면·모듈 단위.
