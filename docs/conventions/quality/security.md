# 보안 규칙

## 비밀값

- 비밀번호·API 키·토큰·인증서를 코드, 커밋, 로그, MR 본문 어디에도 쓰지 않는다.
- 설정값은 환경변수로 읽는다. 로컬은 `.env`(커밋 금지), 키 이름이 추가되면 `.env.example`도 같은 MR에서 갱신한다.
- 운영 설정의 원본은 Jenkins Secret file(.env.config)이다 — 변경 절차는 docs/infra/README.md를 따르고, 서버의 파일을 직접 수정하지 않는다.
- `*.pem`, `*.key`, `.env` 계열은 .gitignore에 있다. AI 에이전트는 이 파일들을 읽지도 수정하지도 않는다 (AGENTS.md).

## 코드

- 모든 외부 입력(요청 본문, 쿼리, BLE 수신값)은 서버에서 검증한다. 클라이언트 검증은 UX일 뿐 방어선이 아니다.
- 로그에 개인정보(이름, 이메일)와 토큰을 남기지 않는다. 학습 기록 로그는 식별자(id)로만.
- 에러 응답에 내부 구조(스택 트레이스, SQL, 파일 경로)를 노출하지 않는다.
- 의존성 추가는 MR에서 사유를 밝힌다 (공급망 검토).

## 자동 검사 (도입 예정)

- pre-commit + gitleaks가 커밋 시점에 비밀값 패턴을 차단한다. 걸렸다면 값을 이미 노출한 것이므로 **해당 키를 즉시 폐기·재발급**하고 커밋에서 제거한다.
